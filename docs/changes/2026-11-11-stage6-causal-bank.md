# Этап 6. Причинная модель LF с фиксированными полюсами

11 ноября 2026. Исследовательский прототип, 44,1 кГц, −36 dBFS. Этап открыт.

## Решение и формат

В скрипте `measurements/scripts/probe_pultec_lf_causal_bank.py` один банк реализует весь отклик, включая flat и обе оси. Низкий ранг ранее измеренного interaction мотивирует интерполяцию небольшого гладкого остатка в плоскости ручек. Здесь остаток аддитивный в пространстве вещественных выходных весов. Комплексный log и его экспоненту вычислять в runtime не требуется. Подгонка одновременно использует измеренные амплитуду и фазу, без предположения о минимально-фазовом характере референса.

Экспорт в `measurements/results/pultec_lf/causal_bank/model.json` содержит полюса и таблицу [CPS][Boost 0…10][Atten 0…10][144]. В начале файла указаны частота и порядок полей. Для каждой из 48 комплексных пар сопряжённых полюсов достаточно одного комплексного состояния на канал:

```
s[n] = p*s[n-1] + (1-abs(p))*x[n]
y[n] = sum(w[k]*x[n-k], k=0..47)
     + dot(w[48..95], real(s[n])) + dot(w[96..143], imag(s[n]))
```

Начальные состояния нулевые. Первые 48 весов образуют причинный FIR прямой свёртки. Есть прямой путь от текущего входа, добавочная буферная задержка равна нулю. Групповая задержка зависит от частоты. Экспорт читается до начала аудиообработки. Существующий шестисекционный каскад этот формат не исполняет.

Осевая таблица построена по 80 измерениям и flat. Для каждого CPS подогнаны 23 совместных отклика; из их весов вычтена сумма двух осей с поправкой на flat. Кубическая RBF с нулевыми осевыми опорами вычисляется офлайн. В выгруженной таблице взаимодействие на осях принудительно нулевое. Для дробных ручек предлагается ограничение диапазона [0,10] и билинейное смешивание четырёх соседних векторов. Оно непрерывно, включая границы ячеек, хотя производные на границах могут различаться. Предлагаемая автоматизация — сглаживание весов за 20 мс, с продолжением от текущих весов при новой команде. Полюса и состояния не переключаются даже при смене CPS.

## Стоимость и решение по выпуску

Хранение весов всех CPS в float32 займёт 272,25 КиБ (4×11×11×144×4 байта). На канал требуется около 576 байт для 48 комплексных состояний и 48 отсчётов истории в float32. Прямая реализация — до 384 вещественных умножений на канал и отсчёт без учёта автоматизации: 48×(4 для комплексного умножения + 1 для входа + 2 для выхода) + 48 для FIR. Для стерео это около 33,9 / 36,9 / 73,7 млн умножений/с при 44,1 / 48 / 96 кГц. Это оценка; фактические CPU, точность float32, автоматизация и работа хоста не проверены. Для других частот нужна отдельная подгонка и сетка проверки, перенос физических частот полюсов сам по себе не переносит FIR и измеренную фазу.

На сетке из 8193 частот просмотрены все 484 табличных состояния. Между измеренными частотами отклик банка отклоняется до 0,262 дБ от линейной интерполяции его собственных отсчётов АЧХ. Это диагностика изгиба кривой; фактическая ошибка между измерениями неизвестна. Выше 18 кГц модель достигает +11,99 дБ. Данных текущих CSV недостаточно, чтобы установить реальный характер этой области. Для следующего эксперимента нужны более плотные независимые частотные значения из сохранённых sweep с проверкой SHA-256, особенно 16–22,05 кГц, и разбор общей для осей и joint компенсированной фазы. Следует проверить flat отдельно: если существенный подъём нужен уже там, увеличение ранга interaction эту причину не устранит.

До проверки плотного спектра прекратить подбор по текущей сетке. Если причинную нулелатентную реализацию в подтверждённых пределах получить не удастся, вынести ограничение совместного режима 1.0 на отдельное продуктовое решение. Текущая поставка и пороги SPEC не менялись.

## Замер после фиксации train-only guard

**Статус: исследовательская проверка пройдена на сохранённой измерительной сетке; runtime/DSP и выпуск не проверены.**

После первоначального holdout результата 307/308 guard был изменён только в train-only процедуре. Для guard=0.003 и ridge=0.0001 сохранены 92/92 прохода на 92 обучающих настройках и максимум +9,49 dB в 18–22,05 kHz. Лишь после фиксации этих параметров скрипт открыл holdout: все 308/308 прошли. Максимальные абсолютные ошибки holdout: 0,14803 dB (20–100 Hz), 0,11436 dB (100–1000 Hz), 0,09742 dB (1–18 kHz), 1,90963° (20 Hz–18 kHz). Подробный поузловой файл — `measurements/results/pultec_lf/causal_bank/frozen_guard003_ridge0001_holdout.csv`; сводка — `measurements/results/pultec_lf/causal_bank/frozen_guard003_ridge0001.json`; воспроизводимый сценарий — `measurements/scripts/tune_pultec_lf_causal_bank_train_only.py`.

Проверенные sweep-кривые уже содержат частотную сетку до 18 kHz, и holdout метрика рассчитана по всей этой сетке. Они не содержат измерений выше 18 kHz: там sweep был ограничен параметром `fmax_hz=18000`. Поэтому +9,49 dB в диапазоне 18–22,05 kHz остаётся предсказанием модели/guard, не измеренной ошибкой против UADx. Следующее действие — отдельный расширенный рендер и анализ референса до Nyquist, с сохранением/проверкой SHA-256 исходного и render WAV; затем сравнить зафиксированную модель без подгонки на новых точках. До этого не включать модель в плагин. Повторно подключать Astra пока не требуется.

### Расширенная проверка по уже сохранённым рендерам

Повторный рендер не потребовался: sweep-источник уже доходит до 0,45×44,1 kHz = 19 845 Hz, а сохранённые UADx WAV ранее анализировались только до 18 kHz. Новый сценарий `measurements/scripts/validate_pultec_lf_causal_bank_extended_band.py` повторно рассчитал transfer по исходным WAV, сверив SHA-256, и сравнил замороженную модель на 240 логарифмических частотах 18–19 845 Hz. Проверены все 484 табличных состояния: 480 доступных измеренных CPS/Boost/Atten настроек плюс четыре CPS flat-точки по сохранённому отдельному flat-рендеру при −36 dBFS. Этот диапазон — диагностический, вне критериев SPEC.

Результат: максимум ошибки модели — 10,387 dB и 91,14°; максимум референсного уровня в диапазоне — +3,684 dB, модели — +9,487 dB. Наиболее проблемная точка — CPS20, Boost10, Atten2, 19 820,7 Hz; ошибка 10,387 dB, фазовая ошибка 87,37°. В конкретной проверенной выше точке CPS100/Boost9/Atten3 ошибка достигла 8,66 dB и 79,04° по расширенной сетке. Значит, guard нельзя принимать как безвредную экстраполяцию: за 18 kHz причинная модель заметно расходится с уже имеющимися рендерами. Модель остаётся кандидатом, не переносить её в рабочий DSP.

Следующий шаг — поручить специалисту узкую train-only доработку HF-ограничителя: обучать/выбирать guard по измеренным данным 18–19 845 Hz только на исходных train-настройках, а затем один раз оценить те же 92/308 разбиения во всём диапазоне 20–19 845 Hz. Не менять/подбирать по holdout, не подменять исходные WAV, сохранять manifest SHA-проверки. Если нового train-only решения, проходящего основные SPEC-гейты и не создающего крупного верхнего подъёма, не получится — обсуждать ограничение полосы модели до 18 kHz или изменение измерительного/продуктового требования отдельно. Артефакты: `measurements/results/pultec_lf/causal_bank/extended_band_validation.json` и `.csv`.
