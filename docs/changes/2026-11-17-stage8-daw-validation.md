## Принятое решение и альтернативы

- **Запись выхода через отдельный armed rec-трек** (src → send → rec). Альтернатива «запись выхода того же трека с айтемом» отвергнута: armed-трек мониторит вход и не играет свои айтемы (проверено диагностическими прогонами recprobe).
- **Seek только WHILE STOPPED, 5 отдельных burst'ов.** Альтернатива «seek во время записи» отвергнута: `SetEditCurPos` seekplay игнорируется в record-состоянии (запись шла линейно, подтверждено корреляцией).
- **Sample-exact выравнивание** (грубо шаг 16, точно шаг 1) вместо только грубого шага 16: на широкополосном сигнале расстройка в 8 сэмплов давала ложный residual ~−10 dB.
- **PID-точный замер CPU и cleanup диалогов** вместо `typeperf \Process(reaper)` и глобального закрытия окон: чтобы не захватить/не закрыть пользовательский REAPER без `-cfgfile`.
- **Офлайн-рендер как эталон realtime-записи** вместо сравнения только с UADx: позволяет отделить дефекты DSP от переходных процессов и поведения эталона.

## Проверки с фактическими результатами

**Реализовано и проверено (realtime, изолированный REAPER, WASAPI shared 96k):** все 8 сессий `DONE`, сбоев нет. Steady-state сегменты AltaiR (play0/reset0/reset0b/wetagain/resume) побитово совпадают с офлайн-рендером: residual −117.8…−119.7 dB rel, max abs 5.96e-08. Bypass dry bit-exact (−109.9 dB). Seek6/seek2 residual −60…−72 dB — установление LF-фильтров после холодного старта (одинаково у AltaiR и UADx), corr ≈ 0.999. UADx steady-state также bit-exact; его wetagain (−49.8 dB) и resume (−98.6 dB) — собственный кроссфейд эталона, не дефект AltaiR. Пауза при записи не пишется в файл (burst5 короче на ~1 с), корректность resume подтверждена.

**Буферы:** запрос 512 → фактический BSIZE 512; запросы 128/64/32 → 288 (период движка WASAPI shared ~3 мс @96k). DSP bit-exact во всех сессиях. Ограничение: настоящие 32/64/128 и переключение SR в realtime недоступны в shared (устройство фиксировано 96k); блоки 32/64/128/512 на уровне VST3 подтверждены pluginval этап 7.

**Нагрузка (CPU % одного ядра, 18 отсчётов, буфер 128→288):** AltaiR 1 инст. median 9.35 / max 46.9; AltaiR 8 инст. median 3.9 / max 73.4; UADx 1 инст. median 10.9 / max 87.5. Отсчёты включают стартовые/петлевые транзиенты; не предельный стресс-тест.

**Офлайн-сравнение рендеров (44.1/48/96k):** низкие (20–100 Гц) и средние (100–1000 Гц) полосы проходят во всех конфигурациях, фаза ≤2°. В 1–18 кГц band-max FFT-кросс-чека превышает 0.10 dB для 60/7/3 (44.1k 0.1166, 48k 0.2079, 96k 0.1059) и 60/10/10 (44.1k 0.1185), p90 в допуске (≤0.054). **Steady-state тоны подтверждают единственную точку превышения SPEC: 60/7/3 @48k/17728 Гц = −0.1717 dB** (допуск 0.10); остальные 6 тонов в допуске. Микс 44.1k level_diff 0.1006 dB (B7/A3) / 0.0568 (B10/A10). Импульсный time-domain на 48/96k — артефакт выравнивания транзиента (argmax ловит звон фильтра), не критерий SPEC.

**Прослушивание:** слепые пары подготовлены и проверены на диске (12 A/B wav @44.1k, RMS-выравнивание, пик 0.8, ключ скрыт). Оценка качества пользователем не выполнена — агент качество не объявляет.

## Ограничения

- Realtime DAW только 96k (устройство фиксировано), буфер ограничен 288 в shared; истинные малые буферы и смена SR в realtime не проверены (покрыты офлайн + pluginval).
- Полосовой FFT по всему sweep — грубый кросс-чек; авторитетна steady-state проверка тонами. Точечная проверка не покрывает каждую частоту HF-пика.
- CPU — один прогон с транзиентами. Второй хост не автоматизирован (ручная процедура в VALIDATION.md §8).
- Слепые пары: поле `rms_altair_before_match` в манифесте фактически содержит post-match значение (косметическое имя, на deliverable не влияет).
