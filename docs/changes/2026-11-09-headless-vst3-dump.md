# Запись: headless VST3-дамп параметров Pultec EQP-1A (этап 2 без REAPER)

Дата: 9 ноября 2026.

Статусы (раздельно): утилита и дамп — реализовано и проверено фактическим прогоном; сетка замеров — перегенерирована (355 задач, 0 условных); паспорт эталона — частично заполнен из дампа; выдержка мануала UA — не получена (страница агенту недоступна); способность плагина обрабатывать сигнал — не проверена (первый рендер на этапе 3).

## Назначение

Выполнить пункты 1–3 чек-листа этапа 2 без участия пользователя и без REAPER: прочитать контракт параметров плагина напрямую из `.vst3` headless JUCE-хостом (без DAW, без аудиоустройства, без UI). Повод: пользователь спросил, способен ли агент сделать четыре шага чек-листа сам.

## Затронутые файлы

- новые `tools/vst3paramdump/CMakeLists.txt`, `tools/vst3paramdump/Main.cpp` — консольный JUCE-хост: `VST3PluginFormat`, загрузка экземпляра, дамп параметров (диапазоны, дискретность, форматированные тексты, зонд квантования по тексту, задержка), JSON-вывод;
- новый `measurements/passports/vst3_dump_pultec_eqp1a.json` — дамп (schema `altair-eq.vst3-dump/1`);
- `docs/REFERENCE_PULTEC_EQP1A.md` — заполнен из дампа (частично, статус в шапке);
- `measurements/scripts/build_grid.py`, `measurements/grid/pultec_lf_grid.json|.csv` — флаги `EQ_IN_CONFIRMED`/`OUTPUT_GAIN_CONFIRMED` = True, группа output_gain развёрнута (5 задач), eq_off стал обязательным;
- эта запись.

## Принятое решение и альтернативы

- Headless-хост вместо ReaScript-дампа в REAPER: даёт сырой контракт параметров VST3 (форматированные тексты, дискретность, закон ручки) без зависимости от хоста и UI; не трогает рабочую DAW пользователя. `dump_fx_params.lua` остаётся как опциональный кросс-чек.
- Зонд квантования ведётся по форматированному тексту: hosted-параметры VST3 в JUCE возвращают установленное normalized-значение при чтении, и закон ступеней виден только в текстовом домене (проверено эмпирически: первая версия зонда по normalized давала 1001 «ступень» у дискретных ручек).
- JUCE подключён внешней зависимостью из родительского проекта (`ALTAIR_JUCE_SOURCE_DIR`), родитель не изменён. Лицензионный вариант JUCE по-прежнему открыт до дистрибуции.
- Альтернатива computer-use в UI REAPER отклонена: длинная цепочка кликов при открытой рабочей сессии пользователя против правила не трогать рабочие DAW.

## Проверки и фактические результаты

- Сборка: cmake configure + build Release успешны (MSVC 19.44, JUCE 8.0.15, пин 91ad83ae34a81e0833b1a2b0866f54846370ae53).
- Прогон: `init ok 1/1` при НЕ запущенном процессе UA Connect (tasklist 09.11.2026) — лицензия читается из кэша; `version_string` = «1.2.16», совпадает со скриншотом-паспортом.
- Дамп: 2092 параметра = 12 органов управления + 2080 служебных MIDI CC; `latency_samples` = 86 @44100 (≈1.95 ms).
- Органы управления: Low Freq дискретный 4 шага (20/30/60/100 CPS, default 30 CPS); LF Boost и LF Atten непрерывные 0.00–10.00, линейно по normalized; Enable Out/In (default In); Output OFF и −12.0…+12.0 dB шаг 0.1 (default 0.0 dB); Power On/Off; Master Bypass Off/On; HF-секция (High Freq 3–16 KCS, HF Boost, HF Q, HF Atten Freq 5/10/20 KCS, HF Atten) — вне scope MVP.
- Сетка: `build_grid.py` перегенерирован — 355 строк, conditional 0, дубликатов ID 0; JSON и CSV согласованы.
- Аудиообработки не выполнялось: ни одного рендера, ни одного измерения АЧХ.

## Ограничения

- Дамп-JSON ≈3.1 МБ: включает 2080 MIDI CC-параметров как сырой артефакт; не ужимал, чтобы не терять полноту.
- Инициализация успешна, но процессинг не проверен: первый офлайн-рендер (этап 3) является проверкой способности экземпляра обрабатывать сигнал.
- Нормализованные границы ступеней (0.167/0.5/0.834…) — границы зон probe-сетки из 1001 точки, а не точные plain-значения VST3.
- Мануал UA не получен: help.uaudio.com отдаёт агенту 403/fetch failed; пункт 4 чек-листа остаётся за пользователем.
