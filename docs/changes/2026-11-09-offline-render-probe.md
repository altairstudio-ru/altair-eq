# Офлайн-рендер: первый проверочный прогон

Дата: 9 ноября 2026. Статус: инструмент реализован и собран; этап 3 не завершён.

## Назначение и решение

Добавлен `tools/vst3render/Main.cpp`, цель `vst3render` в CMake проекта
`tools/vst3paramdump`. Хост читает stereo WAV, обрабатывает блоками 512,
пишет 32-bit float WAV и JSON с фактическими параметрами, версией, SR и
заявленной задержкой. Перед входом пропускает секунду тишины. Задержка
не вырезается; вход должен включать запас тишины для хвоста.
Есть прозрачный режим и установка параметров `index=normalized`.
Существующие выходные WAV не перезаписываются.

`measurements/scripts/check_render.py` создаёт импульс −18 dBFS, 44.1 kHz,
4 секунды, на отметке 1 s, и анализирует null, максимум, stereo и SHA-256.
Пиковое выравнивание — диагностическое: оно не заменяет оценку задержки
окрашенного тракта кросс-корреляцией.

Основной путь — отдельный JUCE-хост согласно уточнению этапа 3. REAPER
остаётся альтернативой для проверки. Рабочая сессия DAW не изменялась.

## Фактические проверки

- Release `vst3render.exe` собран в `build-tools/vst3render_artefacts/Release/`.
- CTest исходного DSP: 1/1 PASS, 0.04 s.
- Прозрачный рендер: bit-identical samples, null peak 0, stereo difference 0.
- UADx default и LF Boost=10: **также bit-identical samples**, пиковый сдвиг 0,
  заявленная задержка после подготовки 0. Это противоречит ожидаемой проверке
  действия Boost и предыдущему паспортному значению 86 samples.
- В JSON Boost=10 подтверждён параметром; успешный вызов processBlock и
  создание WAV не доказывают, что внутренний DSP UADx активирован.
- Явное включение шин не устранило прозрачный результат.
- Проба с dispatch message loop зависла и была остановлена; этот вариант
  удалён из исполнения. Причина не установлена, лицензионная ошибка не доказана.

Артефакты: `measurements/renders/calibration/transparent*`, `pultec-default*`,
`pultec-boost10-buses*` (локальные WAV/JSON). WAV исключены из Git.

## Ограничения и следующий шаг

Не считать эти UADx-рендеры измерением АЧХ. Полную сетку не запускать.
Следует проверить lifecycle/message thread и режим realtime/offline хоста,
затем при необходимости сравнить с отдельным REAPER-проектом.
Калибровка известным фильтром, sweep-анализ, фаза, компенсация задержки и
повторяемость остаются открыты. SHA-256 записывается анализатором, а не
самим renderer; формат паспорта ещё предварительный.

DSP продукта, состояние и интеграция не менялись; миграция не нужна.
Откат: убрать цель renderer, его исходник и диагностический Python-скрипт.

## Продолжение 9 ноября: ошибка загрузки UADx

Реализовано и проверено:

- Аудиообработка перенесена в отдельный поток, главный поток обслуживает
  очередь сообщений Windows. prepare/release остаются на главном потоке.
- Добавлен `--realtime` для сравнения VST3 kRealtime с kOffline. Это режим
  процессора, а не воспроизведение с реальной скоростью или через аудиокарту.
- Повторная подготовка, realtime и обработка в отдельном потоке не устранили
  прозрачный проход. Пиковый сдвиг 0, null 0 в threaded-пробе.
- При обслуживании сообщений обнаружено окно самого `vst3render.exe`:
  **Unable to load UADx Pultec EQP-1A EQ. / Please open UA Connect.**
  Это фактическая ошибка загрузки UADx; конкретная причина работы UA Connect
  или лицензирования не установлена. UA Connect присутствовал в списке
  приложений, но его окно было свёрнуто; состояние продукта не прочитано.
- Инициализационный dispatch до prepare выявляет модальное сообщение и может
  ждать пользователя, поэтому эта диагностическая проба удалена из renderer.
- Добавлен `--require-latency=N`: при несовпадении после prepare процесс
  завершает работу с ошибкой до создания WAV/JSON. Для этого экземпляра
  @44.1 kHz использовать `--require-latency=86` по существующему паспорту.
  Это защитная проверка, а не доказательство корректности DSP при совпадении.
- Release пересобран. Защитный прогон с 86 отклонён (получено 0), WAV и JSON
  не созданы. Прозрачный рендер после изменения поточной модели: null 0,
  сэмплы бит в бит, stereo difference 0.

Следующий шаг: открыть UA Connect и проверить доступность Pultec/авторизацию,
затем повторить защищённую Boost-пробу. Старые прозрачные UADx-рендеры
остаются диагностическими и не используются как reference. Калибровка
известным фильтром и полная сетка по-прежнему не выполнены.

### Повтор после подтверждения UA Connect пользователем

Пользователь прислал скриншот: Pultec Passive EQ Collection v1.2.16,
PERPETUAL, INSTALLED. Установку коллекции не считать отсутствующей.
Защищённый рендер повторён: latency 0, файл не записан.
Повторён также прежний `vst3paramdump.exe`, без изменений его исходника:
init_ok=true, но latency уже 0 (раньше 86). Артефакт сравнения:
`measurements/passports/vst3_dump_pultec_recheck.json`.
Следовательно, расхождение воспроизводится и вне нового renderer;
конкретная причина остаётся неизвестной. Следующая независимая проверка —
загрузка экземпляра в отдельном тестовом проекте REAPER. Скриншот установки
не заменяет проверку обработки в хосте. Просить переустановить коллекцию
на основании имеющихся данных не требуется.
