## Архитектура стенда

Основной путь — headless JUCE-хост `tools/vst3render` (без REAPER, звуковой
карты и UI): читает stereo WAV, обрабатывает блоками 512, пишет 32-bit float
WAV и JSON-паспорт (`altair-eq.render/1`). Перед входом пропускает 1 с тишины
для установления сглаживания. Задержка НЕ вырезается; вход содержит поля
тишины под хвост. Существующие WAV не перезаписываются. Параметры ставятся
по индексам дампа (`index=normalized`). `--require-latency=N` отклоняет рендер
до записи при несовпадении заявленной задержки после prepare.

UADx Pultec обрабатывает сигнал только при запуске вне sandbox (IPC/служба
лицензирования); в ограниченном окружении даёт прозрачный проход и latency 0.
Поэтому для UADx обязателен запуск вне sandbox и защита `--require-latency`.
Совпадение latency само по себе не доказывает корректность DSP — проверяется
действие параметра и сигнал. См. `docs/changes/2026-11-09-uadx-sandbox-resolution.md`.

REAPER — перекрёстная проверка и fallback, не основной путь. Подготовлены
`measurements/scripts/calibrate_reaper.lua` и `eq_reaper_project/stage3-calibration.rpp`
(REAPER 7.85, action ID рендера проверены локально). Особенности setups:
`TrackFX_SetEQParam` для gain принимает линейный множитель, не dB (значение 6
дало +15.6 dB в логе); входной `calibration-impulse-44100.wav` не был создан;
формат рендера в проекте — 24-bit, не 32-float. REAPER-проект НЕ используется
как калибровочное доказательство, пока рендер и аналитическое сравнение не
выполнены отдельно. Рабочая сессия DAW пользователя не изменяется.

## Сигналы

Генератор `measurements/scripts/gen_signals.py`, спецификации совпадают с
сеткой `measurements/grid/pultec_lf_grid.json`:

- `impulse`: 5 с, 200 ms тишины до импульса, пик 0 dBFS.
- `sweep_log`: лог-sweep 1 Hz…0.45·SR, 15 с, фейды 50 ms, −12 dBFS;
  поля тишины 0.5 с до и 2 с после.
- `sine_{50,100,1000}`: 10 с, уровни −36/−24/−18/−12/−6 dBFS, фейды 10 ms.
- `twotone_50_1000`: 10 с, соотношение амплитуд 4:1 (50:1000), уровни −12/−6 dBFS.

Все файлы — stereo 32-bit float WAV, dual-mono. SR: 44100/48000/96000.
WAV хранятся в `measurements/signals/` (gitignored). Манифест с SHA-256,
длительностями, уровнями и пиками — `measurements/results/signals_manifest.json`
(коммитится). Зависимости: `measurements/requirements.txt` (numpy, scipy).

## Паспорт опыта

Каждый рендер сопровождается JSON от renderer (`altair-eq.render/1`): версия
плагина, SR, block size, число сэмплов, заявленная и требуемая задержка,
realtime/offline, все параметры (index/name/normalized/text), пути и SHA-вход
не пишется renderer — входной SHA-256 берётся из манифеста сигналов и
добавляется анализатором (`altair-eq.analysis/1`, поле inputs). Один результат
без паспорта не используется как сравнительное доказательство.

## Задержка

Измеряется сквозной сдвиг импульсом: кросс-корреляция вход/выход
(`analyze.py latency`, целые сэмплы). API-репорт (`getLatencySamples`) только
записывается в паспорт и используется как защита `--require-latency`.
Компенсация — в анализе (`analyze.py transfer --latency N`), не вырезанием
сэмплов. Пиковый сдвиг — диагностика, не замена кросс-корреляции.

Импульс 0 dBFS подходит для оценки временного сдвига, но impulse-transfer
сравнение с sweep на −12 dBFS требует линейности DUT. При уровневой зависимости
не считать их разницу погрешностью стенда. Для проверки изменения АЧХ/фазы с
уровнем использовать серию sweep одного типа при нескольких уровнях; импульс
оставить для latency/временной характеристики.

## Калибровочные допуски (зафиксированы до прогонов)

Гейт этапа 3, все пункты на 44.1 kHz:

1. **Transparent null:** выход бит-в-бит равен входу, difference peak = 0,
   stereo difference = 0.
2. **Известный фильтр против аналитики:** АЧХ ≤ 0.05 dB и фаза ≤ 1.0°
   в полосе 20 Hz–18 kHz, BOTH путями анализа (FFT импульса и деконволюция
   sweep). Эталон фильтра — собственный `tools/calfilter` (RBJ peaking,
   f0 = 1000 Hz, +6 dB, Q = 1.0, zero-latency), аналитика независимо
   реализована в `analyze.py` по тем же формулам RBJ Cookbook.
   Замена ReaEQ из плана: ReaPlugs — VST2, хост поддерживает только VST3;
   REAPER в sandbox не стартует (ошибка 623), setup имеет особенности выше.
   Собственный калибровочный фильтр точно воспроизводим и проверяет ту же
   цепочку рендер→анализ, что используется в этапе 4.
3. **Повторяемость:** повторный рендер той же конфигурации в новом процессе —
   бит-в-бит идентичные сэмплы и совпадающий SHA-256 WAV.
4. **Измерение задержки:** кросс-корреляция даёт 0 сэмплов для calfilter и
   86 сэмплов для UADx flat @44.1 kHz (совпадает с API-репортом и паспортом).
   Для 48/96 kHz задержка UADx измеряется до соответствующих рендеров сетки.

Допуск фазы 1.0° — предложение, зафиксированное до теста; численный результат
проверяется фактически, не подгоняется.

## Что НЕ заявляется

Диагностическое FFT-отношение импульсов UADx (activation probe) подтверждает
действие параметра, но не является калиброванной АЧХ нелинейного плагина и не
используется для подгонки DSP. Субъективное качество, DAW-совместимость и
модель Pultec на этапе 3 не подтверждаются. Полная сетка (этап 4) запускается
только после закрытия гейта выше.
