## Этап 3. Измерительный стенд и калибровка

Основная архитектура: **ReaScript (Lua) в выделенном экземпляре REAPER на отдельном тестовом проекте**.

- `measurements/scripts/render_grid.lua`: цикл конфигураций → `TrackFX_SetParam`/`TrackFX_SetEnabled` → настройка рендера через `GetSetProjectInfo` (32-bit float WAV, dither off, resample off, tail фиксирован) → команда рендера (точные action ID проверить на 7.85 локально, не хардкодить по памяти) → паспорт опыта в JSON рядом с wav.
- Ядро рендера (основной вариант после дампа 09.11.2026): офлайн sweep/импульс через плагин на том же headless JUCE-хосте (`tools/vst3paramdump` → будущий `tools/vst3render`), без REAPER и звуковой карты; параметры ставятся по индексам/текстам из дампа. ReaScript-схема (`render_grid.lua`) остаётся перекрёстной проверкой поведения в хосте и fallback.
- Fallback 1: `reaper.exe -renderproject <копия.rpp>` — проект на конфигурацию, батч без UI.
- Fallback 2: ручные рендеры пользователем по чек-листу протокола, если UADx ограничивает автоматизацию/офлайн-рендер.
- Задержка: измерять сквозной сдвиг импульсом (кросс-корреляция), API-репорт (`TrackFX_GetLatency`/PDC) только записывать в паспорт; компенсация в анализе.
- Сигналы: `measurements/scripts/gen_signals.py` — единичный импульс с полями тишины, лог-sweep (~1 Hz…0.45·SR, фейды), контрольные синусы 30/50/100/150/300/1k/3k/6k/10k/15k/18k Hz, двухтоновый, уровневая лестница −36…−6 dBFS. SHA-256 каждого входа — в паспорт.
- Анализ: `measurements/scripts/analyze.py` (numpy/scipy; зависимости в `measurements/requirements.txt`).
- Калибровка до измерений эталона: (а) transparent path — null-тест входа и рендера; (б) ReaEQ с известной настройкой против аналитической АЧХ (RBJ-формулы), допуск зафиксировать до теста (предложение: ≤0.05 dB, 20 Hz–18 kHz); (в) повторный рендер той же конфигурации — идентичность/ограниченное расхождение.

Документ: `docs/MEASUREMENT_PROTOCOL.md` (паспорт-формат, процедура, калибровочные допуски, компенсация задержки) + changes-запись.

**Гейт:** transparent null в допуске; ReaEQ совпал с теорией; задержка измерена и компенсируется; повторяемость подтверждена.

## Этап 4. Программа измерений Pultec LF

Сетка, каждый опыт с паспортом:

1. **Boost only:** CPS {20, 30, 60, 100} × ручка 0–10 (+ промежуточные значения, если дамп показал непрерывность), Atten = 0. Sweep + импульс.
2. **Atten only:** симметрично.
3. **Boost+Atten одновременно на том же CPS:** пары B=A ∈ {2,4,6,8,10}, (10,5), (5,10), (8,2), (2,8) × 4 CPS. «Low-end trick» измерять, не выводить из суммы shelf.
4. **Служебные состояния:** EQ off / все ручки 0 / host bypass — против transparent (окраска тракта плагина, makeup-усилителя).
5. **Выходной Gain/trim** (если подтверждён этапом 2): влияние на АЧХ и уровень.
6. **Уровневая зависимость:** синусы 50/100/1000 Hz на −36/−24/−18/−12/−6 dBFS, flat и характерная настройка (CPS 60, B=6, A=4): усиление от уровня, THD/гармоники, двухтоновый IMD. Решает вопрос «линейный MVP или нужен character».
7. **Sample rates:** полная сетка на 44.1 kHz; сокращённая (CPS {30,100}, B/A ∈ {3,7,10}, trick-пары) на 48 и 96 kHz.
8. **Фаза/group delay** из sweep; предзвон/хвост импульса после вычитания обычной задержки.

Артефакты: `measurements/results/pultec_lf/*.csv|json`, `docs/RESULTS_PULTEC_LF.md` (измерения отдельно от гипотез о схеме) + changes-запись.

Подготовлено заранее (08.11.2026): сетка `measurements/grid/pultec_lf_grid.json|.csv` — 355 заданий (0 условных после дампа 09.11.2026: EQ IN и Output подтверждены), генератор `measurements/scripts/build_grid.py`. Рендеры полной сетки присутствуют в `measurements/results/pultec_lf/render_manifest.json`; все 355 отмечены complete. Дополнительная серия из семи sweep-рендеров сравнила уровни −36/−24/−12 dBFS для flat и CPS60/B6/A4; см. `docs/RESULTS_PULTEC_LF.md`. Гейт этапа 4 остаётся открыт до пользовательского review области данных и решения, достаточно ли их для SPEC или нужно расширить sweep-level сетку на крайние настройки LF. Исходная подготовка сетки: `docs/changes/2026-11-08-passport-template-and-measurement-grid.md`.

**Гейт закрыт 10.11.2026 для согласованного scope LF MVP:** все результаты имеют паспорта; три случайные конфигурации и дополнительный sweep-повтор побитно повторились; на CPS60/B6/A4 подтверждено изменение кривой с уровнем (до 0.181066 dB / 1.794594° между −36 и −12 dBFS). Пользователь утвердил линейную низкоуровневую модель и исключил нелинейный характер из этого MVP. Результаты и ограничения: `docs/RESULTS_PULTEC_LF.md`.

## Этап 6. DSP-компонент и golden-тесты

**Статус на 11.11.2026: в работе; точечный offline-fit гейт закрыт, гейт переноса в DSP открыт.**

Шестисекционная offline-подгонка с ограничением радиуса r≤0,999 проходит точечные метрики на всех 152 measured nodes (44,1 kHz: 116/116; 48 kHz: 18/18; 96 kHz: 18/18). Теоретическое float32-квантование дало 0/912 секций с радиусом ≥1 (максимум 0,999246). Это offline-fit и расчёт коэффициентов, не готовый DSP и не результат golden-тестов. Подробно: `docs/changes/2026-11-10-stage6-fit-probe.md`.

Калибровка анализатора известным фильтром пройдена при 44,1/48/96 kHz на тех же sweep-сигналах сетки; сводка `measurements/results/calibration/stage6-sweep-calibration.json`. Простое root-scaling прошло 0/36 межчастотных проверок; билинейное отображение с перенастройкой gain — 25/36 (48 kHz: 18/18; 96 kHz: 7/18). Следующий шаг: определить и проверить интерполяцию параметров SOS между точками ручек при каждом sample rate; не переносить пока одну модель между SR. Затем реализовать `dsp/PultecLf.h` (`SourceEq.h` не трогать) и golden-тесты.

`tests/PultecLfTests.cpp` + `tests/golden/pultec_lf_*.csv` (коммитятся): сравнение с измеренными кривыми на контрольных частотах в допуске SPEC, раздельные метрики ошибки АЧХ и фазы, нейтраль/bypass = точное unity, регистрация в CTest. `docs/ARCHITECTURE.md` + changes-запись.

**Гейт:** golden-тесты PASS на 44.1/48/96 kHz; отчёт ошибок по каждой точке сетки (не «красивый график»); click/automation-тест пройден.

## Риски

- UADx: ограничения offline-рендера/авторизации UA Connect — проверить на transparent+импульсе до всей сетки; fallback — ручные рендеры.
- Задержка UADx (возможный внутренний oversampling) — компенсация импульсом обязательна, доверие только API-репорту — нет.
- Гранулярность ручек неизвестна до дампа; нормализованные значения `TrackFX_SetParam` могут квантоваться иначе, чем UI.
- REAPER 7.85: action ID рендера, форматные настройки, tail/dither/resample — проверять локально, не хардкодить по памяти.
- Мануал UA недоступен агенту (403) — факты кроме подтверждённого фрагмента CPS сверяет пользователь.
- Нелинейность эталона может сделать LTI-подгонку недостаточной — решение на гейте этапа 4.
- Дрейф коммита JUCE родителя (пин зафиксирован); объём рендеров на диске (сотни wav на 3 SR) — контроль в протоколе.
